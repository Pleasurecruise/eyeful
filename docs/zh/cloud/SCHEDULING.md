# 审查生命周期

workflow `.github/workflows/eyeful.yml` 决定何时审查。每次审查是一个 job；同一个 pull request 同时最多跑一个。

| 机制     | 行为                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------- |
| 一次     | pull request 打开或转为可审查时审查。草稿不审。                                                    |
| @        | 在打开的 pull request 上以 `@eyeful-review` 开头的评论，会审查它当前的 head。                      |
| 谁可以   | 只有关联身份为 `OWNER`、`MEMBER` 或 `COLLABORATOR` 的 pull request 作者或评论者能发起审查。        |
| 排队     | 每个 pull request 一个 `concurrency` 组，新审查排在正在运行的之后；更新的 @ 会替换还在排队的那个。 |
| 已关闭   | 在已关闭的 pull request 上 @，job 直接结束，不做审查。                                             |
| CI       | 审查等待 head 提交上其他所有 workflow 运行结束，不等它自己。                                       |
| 检查     | job 本身就是检查：审查失败时它失败。由 @ 触发的运行不挂在 head 提交上。                            |
| 重新运行 | 重新运行 job 会从头审查，只发布缺少的内容。                                                        |
| 超时     | job 120 分钟后停止。                                                                               |
| 沙箱     | 每次审查有自己的沙箱容器，job 结束时删除。                                                         |

## 还没做的

- 审查在 job 里等 CI，pull request 的检查跑着时一直占用一台 runner。
- 由 @ 触发的审查还不会复用上一次审查的发现。
- 镜像每个 job 都重新构建，没有从镜像仓库拉取。
