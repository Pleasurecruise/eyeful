# 原则

作者的八条工作习惯。它们是提醒，不是审查的依据：依据是[参考资料](REFERENCES.md)里的文献，两者不一致时以文献为准。

| 原则           | 在开发中                                 | 在审查中                                                         |
| -------------- | ---------------------------------------- | ---------------------------------------------------------------- |
| 第一性原理     | 先复现问题、找到原因                     | 阻塞的发现需要一个失败的测试和[判定依据](VERIFICATION.md#oracle) |
| 对抗式审查     | 由没有参与构建的人来找反例               | 专家不是改动的作者，测试结果只由验证器记录                       |
| 消融           | 去掉后测不出变化的部分就去掉             | 只有[评估](EVALUATION.md#ablations)显示有用的专家才保留          |
| 奥卡姆剃刀     | 先做能用的最小版本                       | 没有审查能走到的路径就删除（见[层级](LEVELS.md)）                |
| 不确定性清单   | 每次交接列出哪些缺少证据                 | 每份报告以缺席的专家、没能复现的发现和跳过的运行结尾             |
| 独立思考       | 各自得出结论再比较                       | 专家看不到彼此的输出                                             |
| 批判性思考     | 说明什么能推翻一个解释                   | 每条发现都标明它的[证据类型](VERIFICATION.md#evidence-kinds)     |
| 高内聚、低耦合 | 划清边界，让一个部分需要的上下文容易说清 | 每个 agent 拿到自己的文件、skill 和计划                          |
