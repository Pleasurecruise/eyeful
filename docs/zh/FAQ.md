# 常见问题

## 到底审查的是什么？

一个快照：基准提交，加上一个包含被审查代码的提交，在任何东西运行之前就固定下来。

- 在本地，默认是相对于 `HEAD` 的未提交改动。`--base` 改为和 merge base 比较，`--head` 审查某个提交或分支（见[可以审查什么](LOCAL.md#what-can-be-reviewed)、[快照](LOCAL.md#snapshot)）。
- 在云端永远是 pull request，每次推送都是新的快照（见[云端运行](CLOUD.md#what-can-be-reviewed)）。

## 改动太大怎么办？

分拣会把 diff 超过 512 KB 的文件放到一边。剩下的部分超过 2,000 行改动时，Go 按目录把它拆成若干范围，每个范围用一份预算单独规划和审查（见[大型改动](PLANNER.md#large)）。

## 审查过程中文件变了怎么办？

被审查的代码不会变，因为快照已经先固定下来了。

| 谁改的                        | 会发生什么                                       |
| ----------------------------- | ------------------------------------------------ |
| 用户，在工作区里              | 项目命令不受影响。eyeful 在结束时报告差异        |
| 项目命令                      | 它在 eyeful 的检出里运行，每次运行后都会重置     |
| agent                         | 它只有只读工具。有变化会在结束时报告             |
| pull request 的新推送（云端） | 是一次新的审查，正在运行的那次在自己的快照上跑完 |
